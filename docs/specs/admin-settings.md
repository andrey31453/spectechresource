# Спека слайса `admin-settings` — настройки сайта и города

| | |
|---|---|
| Статус | ✅ реализовано и проверено 16.11.2026 (dev `:3999`, 227 unit-тестов) |
| Слайс | админ-API настроек (`settings`, `cities`) и экран `/admin/settings` |
| Не входит | уведомления о заявках, реквизиты в PDF, мультигород с разными телефонами, роли (ADR-20) |

## Зачем

Телефон, мессенджеры, адрес, реквизиты и счётчик Метрики сейчас меняются только сидом или Prisma Studio.
Без этого экрана запуск невозможен: любая правка контактов требует разработчика. Публичный `/api/site`
читает те же таблицы, кэша страниц нет — после сохранения изменения видны сразу.

`SiteSettings` — singleton с `id = "main"`. `City` нужен, потому что `cityId` обязателен, а город
в сиде один: без управления городами поле нечем заполнить при переезде в другой город.

## Контракт API

Все хэндлеры под `/api/admin/**`: middleware проверяет сессию и CSRF, в каждом хэндлере —
`requireAdmin(event)` (ADR-19, ADR-20). Ошибки — в общем формате
`{ message, data: { errors: [{ field, message }] } }`.

| Метод и путь | Назначение | Успех |
|---|---|---|
| `GET /api/admin/settings` | настройки + все города (включая неактивные) | `{ settings, cities }` |
| `PATCH /api/admin/settings` | сохранить настройки целиком (форма шлёт все поля) | `{ settings }` |
| `POST /api/admin/cities` | новый город | `201 { city }` |
| `PATCH /api/admin/cities/:id` | правка города, только переданные поля | `{ city }` |
| `DELETE /api/admin/cities/:id` | удаление города | `{ ok: true }` |

Коды ошибок: `400` — схема не прошла, `401` — нет сессии, `404` — города нет,
`409` — занятый `slug` (`P2002`), город используется в настройках, попытка оставить сайт без города.

## Валидация (`shared/schemas/admin-settings.ts`)

Схемы общие для формы и сервера; форма шлёт строки, сервер приводит их к виду Prisma.
Правила `slug`, `sortOrder`, обязательного и необязательного текста переиспользуются из
`shared/schemas/catalog.ts` (`slugField`, `sortOrderField`, `requiredText`, `optionalText`).

| Поле | Правило |
|---|---|
| `companyName` | обязательный текст, 2–200 символов |
| `phone` | обязательный, 10–25 символов, только цифры, пробел, `+ ( ) -`; отображаемый вид, не нормализуется |
| `email` | необязательный, `name@example.ru` |
| `telegram`, `whatsapp`, `maxMessenger`, `workingHours`, `address` | необязательный текст (`200`, `200`, `200`, `120`, `300` символов) |
| `cityId` | обязательный; существование проверяет хэндлер → `400` с полем `cityId` |
| `mapLat`, `mapLng` | необязательные числа; принимаются строки и запятая (`«55,75» → 55.75`), пусто → `null`; `-90…90` и `-180…180` |
| `legalName`, `legalAddress` | необязательный текст, до 255 символов |
| `inn` | необязательный, 10 или 12 цифр |
| `ogrn` | необязательный, 13 или 15 цифр |
| `priceDisclaimer` | обязательный текст, 2–300 символов |
| `metrikaId` | необязательный, 1–10 цифр (пусто — счётчик не подключается) |
| `City.slug` | по правилам каталога: 2–80 символов, латиница в нижнем регистре, цифры, дефис |
| `City.name`, `City.nameIn` | обязательные тексты до 120 символов; `nameIn` — предложный падеж для H1 «Аренда … в Москве» |
| `City.sortOrder` | целое 0…100000, по умолчанию 10 |
| `City.isDefault`, `City.isActive` | boolean; при создании `false` и `true` |

## Правила городов

- `isDefault: true` снимает флаг с остальных городов в одной транзакции — дефолт всегда один.
- Деактивировать последний активный город нельзя (`409`): `landing.get.ts` и `sitemap.xml.ts`
  выбирают первый активный город, без него лендинги и карта сайта останутся без города.
- Город, указанный в `SiteSettings.cityId`, удалить нельзя (`409`): сначала выбрать другой в настройках.
- Единственный город удалить нельзя (`409`).
- Смена `slug` города редирект не создаёт: публичные адреса лендингов строятся от вида техники
  и города по умолчанию, отдельной страницы города нет.

## Видимость изменений

Публичный `/api/site`, `/api/landing` и `sitemap.xml` читают PostgreSQL на каждый запрос,
кэша нет — сохранение в админке видно на сайте сразу. Если появится кэш страниц, инвалидацию
добавить в `PATCH /api/admin/settings`.

## Проверено 16.11.2026 (dev на `:3999`)

- Без cookie `GET /api/admin/settings` → `401`; страница `/admin/settings` → `302` на вход с `next`.
- `PATCH` с телефоном «abc» → `400`, две ошибки по полю `phone` (длина и формат).
- `PATCH` с телефоном `+7 (495) 111-11-11` → `200`, `/api/site` сразу отдаёт новый телефон
  (после проверки настройки возвращены к значениям сида).
- `POST` города `test-gorod` → `201` (`isDefault: false`, `isActive: true`, порядок 10);
  повторный `POST` с тем же кодом → `409`.
- `PATCH` тестового города `{ isDefault: true, isActive: false }` → `200`, у Москвы флаг
  «по умолчанию» снят; город, указанный в `SiteSettings.cityId`, удалить нельзя → `409`.
- `PATCH` Москвы `{ isActive: false }`, когда она единственная активная → `409`;
  `DELETE` единственного города → `409` («Нельзя удалить единственный город»).
- Тестовый город удалён (`200`), настройки и Москва (`isDefault: true`, `isActive: true`) возвращены;
  в БД остался один город.
- `/admin/settings` с cookie → `200` (секции «Компания и контакты», «Города», таблица городов);
  без cookie → `302` на вход.
- `npm run lint` — чисто; `npm test` — 227/227; `npm run typecheck` — без ошибок; `npm run build` — успешно.

## Ограничения (осознанные)

- Настройки сохраняются целиком: параллельная правка двумя администраторами перезапишет
  более раннюю — для одного контент-менеджера это приемлемо, блокировок нет.
- Загрузка логотипа и favicon в настройки не входит: в схеме БД таких полей нет.
- `metrikaId` хранится строкой и не проверяется через API Метрики.
