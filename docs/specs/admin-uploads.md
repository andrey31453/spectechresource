# Спека слайса `admin-uploads` — загрузка изображений

| | |
|---|---|
| Статус | ✅ реализовано и проверено 16.11.2026 (dev `:3999`, 211 unit-тестов) |
| Слайс | приём, отдача, удаление изображений и очистка «сирот» |
| Не входит | ресайз/WebP-конверсия и `<NuxtImg>` (`@nuxt/image` — слайс фронтенда), медиа-библиотека, S3 |

## Зачем

Фотографии разделов, видов и моделей заказчик загружает из админки, а не вставляет адреса вручную.
Файлы лежат на сервере, публичные страницы получают готовый `/uploads/…` и не зависят от внешних CDN.

## Хранение (ADR-21)

- Папка: `UPLOADS_DIR`, по умолчанию `.data/uploads` от корня проекта (`.data/` в `.gitignore`).
- **Не `public/`**: при `nuxt build` содержимое `public/` копируется в `.output/public` один раз,
  поэтому файл, загруженный в проде после сборки, оттуда не отдаётся.
- Раскладка: `<год>/<месяц>/<uuid>.<ext>` — в месяце не бывает тысяч файлов, а имя уникально навсегда.
- Имя генерирует сервер: исходное имя файла в путь не попадает (кириллица, пробелы, `../`).
- Публичный адрес файла — `/uploads/<год>/<месяц>/<uuid>.<ext>`; в БД хранится именно он.

## Контракт

| Метод и путь | Назначение | Успех | Ошибки |
|---|---|---|---|
| `POST /api/admin/uploads` | `multipart/form-data`, поле `file` | `201 { upload }` | `400` — нет файла, больше 5 МБ, формат не распознан; `413` — тело заметно больше лимита; `401` — нет сессии |
| `DELETE /api/admin/uploads/:path` | удалить файл с диска | `{ ok: true }` | `404` — файла нет или путь не наш; `409` — файл используется в БД |
| `GET /uploads/:path` | публичная отдача | файл с `Content-Type` | `404` — нет файла или путь не наш |
| задача `uploads:cleanup` | удалить «сирот» | `{ scanned, referenced, removed, keptRecent }` | — |

`upload` в ответе: `{ path, url, size, mime, originalName }` — зеркало `app/types/admin-uploads.ts`.
`409` при удалении содержит список мест: `Файл используется: раздел «…», модель «…». Сначала уберите его из этих записей.`

## Валидация

| Правило | Как |
|---|---|
| Формат | по magic bytes (`shared/utils/uploads.ts`): JPEG, PNG, WebP, AVIF, GIF; SVG и текст отклоняются |
| Размер | ≤ 5 МБ; больше — `400` с подсказкой «сожмите изображение» |
| Имя на диске | `<год>/<месяц>/<uuid>.<ext>`, проверяется регуляркой при чтении и удалении |
| Чтение в память | `readMultipartFormData` буферизует файл целиком; `Content-Length` больше 5 МБ + 64 КБ отклоняется сразу (`413`) |
| Расширение файла | берётся из распознанного формата, а не из имени загруженного файла |

## Удаление и «сироты»

- `DELETE` сначала ищет адрес в `categories.image`, `services.image`, `equipment_types.gallery`,
  `equipment_models.photos`; если нашёл — `409`, файл остаётся.
- Задача `uploads:cleanup` удаляет файлы, на которые никто не ссылается, **старше 24 часов**:
  свежая загрузка без сохранённой формы тоже выглядит сиротой, и удалять её сразу нельзя.
- Запуск: `npx nuxi task run uploads:cleanup --url http://localhost:3999`; в проде — по расписанию
  вместе с `leads:send` (TODO, раздел «Прод»).

## Админка

| Компонент | Где |
|---|---|
| `app/composables/useImageUpload.ts` | загрузка/удаление, ошибки в одном формате на все формы |
| `app/components/admin/AdminImageField.vue` | одно изображение: раздел каталога |
| `app/components/admin/AdminGalleryField.vue` | галерея: вид техники, фото модели; стрелки меняют порядок |

В форме — два разных действия: «Убрать» убирает адрес из формы (сохранение запишет новый список),
«Удалить файл» стирает его с диска через `DELETE`. Внешние адреса (`https://…`) удалить нельзя —
сервер отвечает `400`-подобной подсказкой в поле.

## Прод

- `UPLOADS_DIR` указывает на смонтированный volume (иначе файлы исчезнут при пересоздании контейнера).
- Volume входит в бэкап вместе с PostgreSQL.
- nginx: `client_max_body_size 6m;` — иначе 5 МБ не доедут до Nitro.
- Отдача файлов идёт через Nitro; при росте трафика — nginx `alias` на папку или S3-совместимое хранилище.

## Проверено 16.11.2026 (dev на `:3999`)

- `POST /api/admin/uploads` и `DELETE /api/admin/uploads/:path` без cookie → `401`.
- PNG 70 Б → `201`, `{ path: "2026/11/<uuid>.png", url: "/uploads/2026/11/<uuid>.png", mime: "image/png" }`;
  файл появился в `.data/uploads/2026/11/`.
- `GET /uploads/2026/11/<uuid>.png` → `200`, `Content-Type: image/png`, `Content-Length: 70`,
  `Cache-Control: public, max-age=31536000, immutable`, `X-Content-Type-Options: nosniff`.
- Текстовый файл → `400` «Поддерживаются изображения JPEG, PNG, WebP, AVIF и GIF»;
  PNG на 6 МБ → `413` «Файл больше 5,0 МБ — сожмите изображение» (отказ до чтения тела).
- Путь с `../` (`/uploads/2026/11/../../etc/passwd` и то же в `DELETE`) → `404`.
- Удаление непривязанного файла → `{ ok: true }`, повторный `GET` → `404`.
- Файл привязан к разделу (`PATCH categories/:id { image: url }`) → `DELETE` вернул `409`
  «Файл используется: раздел «Землеройная техника»…»; после `image: null` удаление → `200`.
- Задача `uploads:cleanup`: свежий файл → `{ scanned: 1, removed: 0, keptRecent: 1 }`;
  после сдвига mtime на год назад → `{ scanned: 1, removed: 1, keptRecent: 0 }`, папка пуста.
- Страницы `/admin/catalog`, `/admin/catalog/:categoryId`, `/admin/catalog/types/:id` → `200`,
  блоки загрузки отрисовались; тестовые данные и QA-администратор удалены.
- `npm run lint` — чисто; `npm test` — 211/211; `npm run typecheck` — без ошибок; `npm run build` — успешно.

## Ограничения (осознанные)

- Нет ресайза и конвертации в WebP: сервер отдаёт файл как есть, `<NuxtImg>` — слайс фронтенда.
- EXIF не вычищается: для фото техники это не ПДн, но при загрузке фото людей правило придётся добавить.
- Нет drag&drop и прогресса по байтам: файл до 5 МБ загружается одним запросом.
- Медиа-библиотеки нет: список файлов виден только через задачу очистки.
- Одновременная загрузка одного файла в две формы создаст две копии — дубликаты не склеиваются.
