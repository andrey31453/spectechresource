# Одноразовый импорт каталога

## Цель

Собрать товары MSG Spectech и AKS Group в локальный JSON-архив и скачать фотографии
в `.data/uploads`. База данных на этапе парсинга не изменяется.

## Запуск

```bash
npm run catalog:import
# Пробный запуск: до двух карточек каждого источника
IMPORT_MAX_PRODUCTS=2 npm run catalog:import
```

Результат создаётся в `.data/imports/<UTC timestamp>/`: `products.json` и `report.json`.
В архиве нет исходных URL карточек, URL фотографий и HTML. URL используются только во время
запуска. Для каждого товара раздел источника сопоставляется с существующим `EquipmentType`.

## Правила

- найденный `EquipmentType`: `typeId` заполнен, `isPublished: true`;
- ненайденный `EquipmentType`: `typeId: null`, `isPublished: false`;
- характеристики сохраняются массивом `name/value`;
- сохраняются цены за час и смену, если они есть;
- изображения проходят проверку и преобразуются в WebP-варианты существующим обработчиком;
- фотографии хранятся в стандартном `.data/uploads/YYYY/MM/UUID-{small,medium,full}.webp`,
  UUID детерминирован по SHA-256 содержимого; произвольные вложенные пути сервер не отдаёт;
- разделы MSG берутся со страницы каталога, AKS — из меню «Техника»; sitemap ограничивает
  список карточек; один раздел получает один вид, без классификации отдельных товаров;
- неизвестные разделы (например, общий «Аренда экскаваторов») остаются без вида;
- ошибки отражаются в отчёте без URL, неполный сбор возвращает ненулевой код;
- импорт в БД выполняется отдельной командой по `products.json`.

## Загрузка в локальную БД

`npx tsx scripts/load-catalog.ts <каталог архива> --replace-and-clear-leads`
разрешён только для localhost/127.0.0.1:5433. Команда проверяет цены, виды,
дубликаты и все варианты фотографий до замены. Удаляет все заявки и старые
модели (характеристики удаляются каскадно), создаёт модели и характеристики
одной транзакцией. Остальные таблицы и файлы не меняются. Описания сохраняются
в `shortDesc`, статусы публикации — без пересчёта. Коллизии slug получают
числовой суффикс. До коммита все загруженные поля сверяются с архивом;
ошибка вызывает откат. Команда разрушительная, резервную копию не создаёт.

До импорта в БД не запускать `uploads:cleanup`: фотографии архива ещё не имеют ссылок в БД
и через 24 часа могут считаться сиротами. Архив и загрузки исключены из Git.

## Объединение дублей (без записи в БД)

`npm run catalog:deduplicate -- .data/imports/<UTC timestamp>` создаёт новый соседний
каталог `*-merged-<UTC timestamp>`, не меняя исходный архив и фотографии.
Ключ объединения: вид + бренд + модель (без учёта регистра); при неизвестном виде —
источник и исходный раздел вместо вида. Краны, названные только производителем и
грузоподъёмностью, получают грузоподъёмность в поле модели, без выдуманного индекса.

- Фото объединяются по локальному адресу, описания — по уникальным абзацам.
- Характеристики объединяются по названию; одинаковые значения, включая формат
  `4 900`/`4900`, не дублируются. Разные названия автоматически не отождествляются.
- При конфликте числовых характеристик выбирается меньшее значение, товар получает
  `isPublished: false` с сохранением `typeId`. В начале описания — предупреждение
  с исходными вариантами и выбранным значением. Это исключение из правила публикации
  по наличию вида. Нечисловые конфликты и разные единицы останавливают команду.
- За час и смену независимо выбирается минимальная указанная цена; `null` не равен
  нулю. Дублирующие строки «Цена за час/смену» из характеристик объединённых карточек
  убираются: цена хранится в выделенных полях.
- `source`, `sourceSection`, `title` берутся из первой карточки; полный журнал
  объединений и конфликтов хранится в `report.json`, прежние ошибки сбора сохраняются.
- Перед записью проверяются все три варианта фото и отсутствие внешних URL.
  Приёмка: тесты объединения, повторный прогон без изменения результата, проверка
  числа записей, фото и оставшихся ключей-дублей. Полноту первоначального сбора
  дедупликация не подтверждает.
