# Заявки → Rusender

Получатель на время проверки: `andrey31453@gmail.com`; отправитель:
`info@specteh.online` (домен должен быть подтверждён в Rusender).
Клиентские помощники находятся в `app/mail-form`, транспорт — в `server/mail-form`.
PHP-пример из `docs/mail-form` не публикуется и не исполняется.

`POST /api/leads` сохраняет прежний контракт, валидацию, honeypot, rate limit и
идемпотентность. Сначала сохраняет Lead, затем отправляет email. Сбой почты не
отменяет принятую заявку. Повтор requestId не отправляет второе письмо.
Битрикс24 остаётся независимым каналом: пока `LEADS_DRY_RUN=true`, он выключен.

Секрет — серверная переменная `NUXT_RUSENDER_API_TOKEN`; адреса —
`NUXT_RUSENDER_FROM` и `NUXT_RUSENDER_TO`. `NUXT_RUSENDER_ENABLED=true` явно
включает отправку; по умолчанию выключено. Секреты не входят в Git/браузер/логи.

API: POST `https://api.rusender.ru/api/v1/public/emails`, Bearer auth,
`{data:{from,to,subject,html}}`. Пользовательские значения экранируются.
Успех — только HTTP 202 и непустой строковый `data.id` (принятие, не доставка).
Таймаут попытки 10 с, один повтор при сети/5xx. Ключ `lead-email-{id}` и тело
не меняются при сетевом повторе. Редиректы запрещены. Ошибки сохраняют только
HTTP-код/категорию, без ответа провайдера, токена и ПДн.

Отдельные поля Lead: `emailSentAt`, `emailMessageId`, `emailAttempts`,
`emailErrorText`; CRM-поля не переиспользуются. Аддитивная миграция не меняет
существующие данные. `leads:email` вручную обрабатывает до 20 неотправленных
заявок, максимум 6 попыток. Автоматического расписания нет. Старые заявки тоже
попадают в очередь: запускать только после проверки её состава.
Не запускать задачу параллельно; длительная досылка после истечения срока
идемпотентности провайдера может дать дубль — сначала проверить его историю.

Приёмка: unit-тесты транспорта/сервисного слоя с mock fetch, lint, typecheck,
build. Настоящая доставка подтверждается отдельно в Rusender и ящике получателя.
Токен из переписки рекомендуется отозвать и заменить.

Production: workflow берёт GitHub Secret `RUSENDER_API_TOKEN`, передаёт по SSH
stdin в `deploy/configure-mail.py`. Скрипт атомарно обновляет только четыре
`NUXT_RUSENDER_*` в `/opt/spectech/shared/app.env` (0600), остальные настройки
сохраняет. Штатный restart применяет окружение. Без секрета настройки не меняются.
