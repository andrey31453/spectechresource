# Фотографии техники — 24.11.2026

Согласованный слайс: загрузка → три размера → галереи каталога и модели.

- У модели до 20 фото; порядок задаётся существующим AdminGalleryField, первое — обложка. Схема БД `photos: string[]` сохраняется.
- Каждое новое изображение обрабатывается sharp: WebP small ≤480×360 (quality 76), medium ≤960×720 (82), full ≤1920×1080 (86). Вписывание без обрезки, без увеличения; EXIF-ориентация учитывается, метаданные удаляются. GIF/анимированные форматы становятся статичным первым кадром.
- Вход ≤5 МБ и ≤40 млн пикселей; повреждённые файлы — 400 с ошибкой поля file. Ошибки диска — серверная ошибка. Исходник не сохраняется. UUID общий: `<uuid>-{small,medium,full}.webp`, в БД — full. Ответ upload сохраняет url/path/mime/size и добавляет variants. Публикация ссылки только после записи всех трёх файлов; при неудаче частичные файлы удаляются.
- DELETE любого варианта проверяет использование всей группы и удаляет всю группу; cleanup защищает все варианты ссылочного фото, свежие группы не удаляются.
- Каталог /katalog и /arenda-{slug}: все фото доступны в карточке, загружается только выбранная small-версия, стрелки на hover/focus, на touch доступны постоянно; свайп, циклическое листание, индикатор. Кнопки не вложены в ссылку и не вызывают переход.
- Товар: small-миниатюры, medium в основном блоке, full только при открытии native dialog. Стрелки/клавиатура, Escape, кнопка, фон; блокировка прокрутки, удержание и возврат фокуса, очистка на смене маршрута/размонтировании. Пустая/одиночная/битая галерея имеют корректные состояния.
- Старые и внешние ссылки до обработки продолжают работать без выдуманных адресов вариантов. Отдельная команда конвертирует доступные текущие фотографии в комплект и обновляет ссылки без очистки БД; недоступные сообщает, не удаляя ссылки молча.
- Проверки: реальные encode/decode тесты, пути/ссылки/удаление/cleanup/DTO, lint, types, test, build, diff --check; Chrome/CDP и визуальный аудит на 375/768/1280. Safari/iOS отмечаются отдельно, если недоступны. Без миграций, деплоя и отправки заявок.

## Подготовка существующих фотлографий

### Декоративный фон товара

На странице модели — приглушённая сетка точек с шагом 22 px и одна из восьми абстрактных инженерных схем (opacity 0.12). Случайный выбор сохраняется в Nuxt useState по пути страницы: сервер и гидратация используют одну схему; при возврате в рамках клиентской сессии она сохраняется. Декор статичный, aria-hidden, не перехватывает клики. Главная, карточки и галерея не изменены.

Проверки фона: 369 тестов прошли, typecheck/build успешны, lint — 0 ошибок и 3 прежних предупреждения. После финальной правки положения схемы повторены build и 5 профильных тестов. Строгий аудит 375/768/1280: переполнения нет, 4 фото без битых, цели ≥24 px, проверяемые текстовые пары AA, ошибок консоли нет. Повторный Chrome/CDP-прогон подтвердил неизменность схемы при гидратации, точки, opacity, отсутствие анимации и регрессию галереи. Один промежуточный прогон остановился на hover каталога из-за позиции прокрутки; повторный полный прогон успешен. Safari/iOS не проверялись.

Текущие dev-данные подготовлены: 12 комплектов WebP без ошибок; у всех 23 опубликованных моделей есть 2–3 фото. Итоговый HTTP-обход после перезапуска preview на финальной сборке: 73 страницы и 27 уникальных адресов изображений, ошибок нет. Проверка изображений выполнялась GET-запросами: существующий маршрут загрузок не обслуживает HEAD.

`npm run images:prepare` запускает `scripts/prepare-images.ts`: обрабатывает доступные локальные фото, обновляет ссылки категорий, видов, моделей и услуг. Учитывает `NUXT_DATABASE_URL`/`DATABASE_URL`, `NUXT_UPLOADS_DIR`/`UPLOADS_DIR`. Готовые варианты повторно не кодирует. Внешние и недоступные адреса сохраняет и выводит в `failures` с ненулевым кодом завершения. Исходники не удаляет. Только для моделей с исходными демо-фото добавляет остальные фото их вида; вручную выбранные галереи не расширяет.
