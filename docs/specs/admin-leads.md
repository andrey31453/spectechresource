# Спека слайса `admin-leads` — журнал заявок в админке

| | |
|---|---|
| Статус | ✅ реализовано и проверено 16.11.2026 (dev `:3999`, 199 unit-тестов) |
| Слайс | админ-API журнала (`GET /api/admin/leads`, карточка, `retry`, `export.csv`) и два экрана админки |
| Не входит | `leads:purge` (срок хранения ПДн), уведомления о новых заявках, роли (ADR-20) |

## Зачем

Заявка по ADR-5 сначала пишется в `Lead` и только потом уходит в Битрикс24. Пока CRM недоступна
или вебхук не настроен, лиды копятся в базе — администратору нужен журнал: найти заявку, увидеть,
дошла ли она, и повторить отправку. Отдельная «публикация» не нужна, изменения видны сразу.

## Контракт API

Все хэндлеры под `/api/admin/**`: middleware проверяет сессию и CSRF, в каждом хэндлере —
`requireAdmin(event)` (ADR-19, ADR-20). Ошибки в общем формате
`{ message, data: { errors: [{ field, message }] } }`.

| Метод и путь | Назначение | Успех |
|---|---|---|
| `GET /api/admin/leads` | список с фильтрами и пагинацией | `{ leads, total, page, pageSize, pages, counts }` |
| `GET /api/admin/leads/:id` | карточка: контакты, источник, UTM, согласие, доставка | `{ lead }` |
| `POST /api/admin/leads/:id/retry` | повторная отправка в CRM | `{ ok, delivery, lead }` |
| `GET /api/admin/leads/export.csv` | выгрузка по тем же фильтрам | `text/csv` вложением |

`counts` — счётчики вкладок (`all`, `NEW`, `SENT`, `FAILED`) по текущим фильтрам, **кроме статуса**:
выбрав «Ошибка», администратор всё равно видит, сколько всего новых и отправленных.

Коды ошибок: `400` — фильтры не прошли схему, `401` — нет сессии, `404` — заявки нет,
`409` — повтор запрещён (уже отправлена или включён `LEADS_DRY_RUN`).

## Фильтры (`shared/schemas/leads-filters.ts`)

Схема общая для списка и выгрузки; пустые значения не попадают в `where`.

| Параметр | Правило |
|---|---|
| `status` | `NEW` / `SENT` / `FAILED`; пусто или `all` — все; иначе `400` |
| `place` | место формы из `LEAD_PLACES`; пусто — любое |
| `from`, `to` | `ГГГГ-ММ-ДД`, реальная дата; невалидная — `400`; `from > to` — `400` на `to` |
| `q` | до 100 символов; имя, e-mail или телефон в любом виде |
| `page` | 1…∞, по умолчанию 1; мусор приводится к 1 |
| `pageSize` | 10…100, по умолчанию 20; больше — обрезается до 100 |

- **Сутки по Москве.** `from` — начало дня (UTC+3), `to` — `23:59:59.999` этого дня, поэтому заявка
  в 00:30 МСК попадает в свой день, а не в предыдущий.
- **Поиск по телефону.** Запрос нормализуется: `+7 (999) 123-45-67` → точное совпадение `+79991234567`
  и `contains` по цифрам `79991234567`; для цифр без `+7` префикс добавляется. Имя и e-mail ищутся
  `contains` без учёта регистра (`mode: "insensitive"`).

## CSV-выгрузка

`server/utils/leads-csv.ts` + `shared/utils/csv.ts`. Файл открывается в русском Excel двойным кликом:

- UTF-8 **BOM**, разделитель `;`, переводы строк `CRLF`;
- кавычки, `;` и переводы строк экранируются по RFC 4180;
- ячейки, начинающиеся с `= + - @`, получают апостроф — защита от CSV-injection
  (телефон `+79991234567` выгружается как `'+79991234567`);
- даты — московские (`ДД.ММ.ГГГГ, ЧЧ:ММ`);
- не больше `LEADS_EXPORT_LIMIT = 5000` строк, сортировка «сначала новые»;
- имя файла — `leads-2026-11-16.csv`; заголовки `content-type`, `content-disposition`, `cache-control: no-store`.

## Повторная отправка

`POST /api/admin/leads/:id/retry` переиспользует `createLeadDelivery` из слайса `leads` — те же
таймаут, ретраи и запись `attempts`/`status`/`errorText`/`sentAt`/`crmLeadId`, что и в задаче
`leads:send`. Условия:

- `status = SENT` → `409` («уже отправлена в CRM (ID …) — повтор создаст дубль»);
- `LEADS_DRY_RUN` включён → `409` с подсказкой выключить режим: зелёная галочка при пустой CRM хуже ошибки;
- пустой `BITRIX24_WEBHOOK_URL` → `409`;
- ответ CRM с ошибкой → `200 { ok: false, delivery }`: это ожидаемое состояние, заявка осталась в базе,
  попытка записана. UI показывает текст ошибки и обновляет карточку.

## UI админки

| Страница | Что делает |
|---|---|
| `/admin/leads` | вкладки статусов со счётчиками, фильтры (поиск, место, даты), таблица, пагинация, «Экспорт CSV» |
| `/admin/leads/:id` | карточка: контакт, комментарий, источник и UTM, согласие, доставка в CRM, служебные поля, «Повторить отправку» |

- Черновик фильтров отделён от применённых: поиск уходит по кнопке/Enter, вкладки и сброс применяются сразу,
  каждое применение возвращает на первую страницу.
- Ссылка на выгрузку собирается из применённых фильтров без пагинации (`app/utils/admin-leads.ts`).
- Повтор отправки блокируется для `SENT` и во время запроса; результат — плашка над карточкой.
- Стили — `app/assets/css/main.css`, блок «Админка: журнал заявок»; layout `/admin/leads*` — широкий.

## Проверка вживую (dev `:3999`)

- `401` без cookie на списке и выгрузке; `400` на `status=LOST` с ошибкой у поля.
- Фильтры: `status=FAILED`, `q=9991234567`, `q=Иван`, `place=equipment`, диапазон дат, пустой день;
  `counts` не зависят от выбранного статуса.
- Карточка: UTM, версия согласия, комментарий с `;` и кавычками; `404` на несуществующий id.
- `retry`: `SENT` → `409` с ID лида; `FAILED` и `NEW` в dry-run → `409` с текстом про `LEADS_DRY_RUN`.
- CSV: заголовки ответа, BOM (`efbbbf`), 25 колонок в каждой строке, комментарий экранирован,
  телефоны с апострофом, даты по Москве.
- Страницы `/admin/leads` и `/admin/leads/:id` рендерятся с cookie (счётчики вкладок, пагинация, кнопка повтора).

## Ограничения

- Выгрузка — до 5000 строк одним запросом; для больших объёмов понадобится фоновая генерация файла.
- Список обновляется при открытии страницы; после ретрая обновляется карточка, список — при возврате.
- `pageSize` не меньше 10, поэтому при малом числе заявок вторая страница не появляется.
- Права у всех администраторов равные (ADR-20): отдельного «только чтение» для CSV нет.
