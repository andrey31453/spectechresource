# Спека слайса `admin-content` — контент и FAQ

| | |
|---|---|
| Статус | ✅ реализовано и проверено 16.11.2026 (dev `:3999`, 273 unit-теста) |
| Слайс | админ-API контентных блоков и экран `/admin/content` |
| Не входит | тексты разделов и видов (слайс `admin-catalog`), SEO-тексты услуг (`admin-services`), статические страницы (`admin-pages`), история версий, отложенная публикация, drag&drop порядка |

## Зачем

FAQ, преимущества, шаги «Как заказать» и цифры доверия выводятся на главной и на посадочных
(`/api/home`, `/api/landing`, `/api/services/{slug}`) и читаются из PostgreSQL на каждый запрос —
кэша нет, сохранение видно на сайте сразу. До слайса эти блоки менялись только сидом.

Один список FAQ закрывает три места: `GLOBAL` — главная и запасной вариант для посадочных вида,
`TYPE` — страница вида техники, `SERVICE` — страница услуги.

## Контракт API

Все хэндлеры под `/api/admin/**`: middleware проверяет сессию и CSRF, в каждом — `requireAdmin(event)`
(ADR-19, ADR-20). Ошибки — в общем формате `{ message, data: { errors: [{ field, message }] } }`.

| Метод и путь | Назначение | Успех |
|---|---|---|
| `GET /api/admin/content` | всё разом: FAQ, преимущества, шаги, цифры + справочники услуг и видов для формы | `{ faq, advantages, steps, stats, services, types }` |
| `POST /api/admin/content/faq` | новый вопрос | `201 { item }` |
| `PATCH /api/admin/content/faq/:id` | правка только переданных полей | `{ item }` |
| `DELETE /api/admin/content/faq/:id` | удаление вопроса | `{ ok: true }` |
| `POST /api/admin/content/advantages` | новое преимущество | `201 { item }` |
| `PATCH /api/admin/content/advantages/:id` | правка | `{ item }` |
| `DELETE /api/admin/content/advantages/:id` | удаление | `{ ok: true }` |
| `POST /api/admin/content/steps`, `.../steps/:id` (`PATCH`, `DELETE`) | шаги порядка работы | как выше |
| `POST /api/admin/content/stats`, `.../stats/:id` (`PATCH`, `DELETE`) | цифры доверия | как выше |

Коды ошибок: `400` — схема не прошла или у вопроса нет привязки, `401` — нет сессии, `404` — записи нет.
Несуществующий `equipmentTypeId` или `serviceId` → `400` с сообщением «Такого вида техники нет» /
«Такой услуги нет»: проверка идёт запросом к справочнику, а не «на веру».

Отдельной карточки `GET /:id` нет: блоки мелкие, список отдаёт все поля, форма открывается без запроса.
Справочники `services` и `types` (с названием раздела) едут тем же ответом — форме FAQ не нужен второй запрос.

## Валидация (`shared/schemas/admin-content.ts`)

Схемы общие для формы и сервера; `requiredText`, `optionalText`, `sortOrder` — из
`shared/schemas/catalog.ts` (`requiredText` — минимум 2 символа, у `optionalText` пустая строка → `null`).

| Поле | Правило |
|---|---|
| FAQ `scope` | `GLOBAL` · `TYPE` · `SERVICE`; при создании обязательна |
| FAQ `equipmentTypeId` | нужен только для `TYPE`; для остальных областей сбрасывается в `null` |
| FAQ `serviceId` | нужен только для `SERVICE`; для остальных — `null` |
| FAQ `question` | обязательный, 2–300 символов |
| FAQ `answer` | обязательный, 2–3000 символов |
| Преимущество `title` | обязательный, 2–120 |
| Преимущество `text` | необязательный, до 300 |
| Преимущество `icon` | ключ иконки: `[a-z0-9-]`, до 40 символов, приводится к нижнему регистру; пусто → `null` |
| Шаг `title` / `text` | обязательный 2–120 / необязательный до 300 |
| Цифра `value` | строка 1–12 символов («120», «12+», «4,9» — поэтому не `Decimal`) |
| Цифра `unit` / `label` | необязательный до 20 / обязательный 2–120 |
| `sortOrder` | целое 0–100 000; при создании `10` |
| `isPublished` | boolean; при создании `true` |
| `PATCH` | `partial`-схема: отсутствующие поля не попадают в `data` |

### Привязка FAQ при `PATCH`

`PATCH` приходит частичным, поэтому итоговую привязку собирает `mergeFaqTarget(existing, patch)`:
`undefined` — «не меняли», `null` — «очистили». Затем `normalizeFaqTarget` убирает лишние ссылки
(`GLOBAL` — всегда без вида и услуги), а `faqTargetIssue` проверяет, что у `TYPE` есть вид,
у `SERVICE` — услуга. Так `PATCH { scope: "GLOBAL" }` не оставляет «висящую» ссылку на вид,
а `PATCH { scope: "TYPE" }` без вида отвечает `400`, а не создаёт вопрос-сироту.

## Где вопросы видны на сайте

| Место | Что берётся |
|---|---|
| Главная (`/api/home`) | `GLOBAL`, опубликованные |
| Посадочная вида (`/api/landing`) | `TYPE` этого вида; если пусто — `GLOBAL` |
| Страница услуги (`/api/services/{slug}`) | `SERVICE` этой услуги; без запасного списка |

Преимущества, шаги и цифры — только на главной, тоже по `isPublished`.

## Экран

| Путь | Что |
|---|---|
| `/admin/content` | вкладки `?tab=faq` (по умолчанию), `advantages`, `steps`, `stats` |
| `/admin/content?tab=…` | ссылки, а не JS-состояние: вкладка сохраняется в адресе и переживает перезагрузку |

Один `GET /api/admin/content` на страницу: переключение вкладок не ходит в сеть, после сохранения
страница обновляет данные (`refresh`). Каждая секция — компонент со своей таблицей и одной inline-формой
(как разделы каталога): «создать» открывает пустую, «изменить» — заполненную. В форме FAQ выбор области
показывает только нужное поле привязки; для `TYPE` и `SERVICE` — селект из справочника, подпись вида
включает раздел («Землеройная техника · Гусеничные экскаваторы»).

В таблице FAQ видно: вопрос и первые две строки ответа, где встретится вопрос (область и привязка),
порядок, публикация, действия. У остальных блоков — текст/иконка/значение, порядок, публикация.
Удаление — с подтверждением в браузере; ошибка удаления показывается над таблицей.

Ссылки: «Контент» в навигации админки и на дашборде; `/admin/content` открывается в широкой колонке.

## Проверено 16.11.2026 (dev на `:3999`)

- Без cookie `GET /api/admin/content` → `401`; `/admin/content` → `302` на вход с `next`.
- `POST` вопроса `TYPE` без вида → `400`, поле `equipmentTypeId`, «Выберите вид техники»;
  с несуществующим видом → `400`, «Такого вида техники нет».
- `POST` вопроса `SERVICE` → `201`; публичный `/api/services/{slug}` содержит его, `/api/home` — нет.
- `PATCH` только `question` → `200`, область и услуга сохранились, текст на сайте обновился.
- `PATCH { scope: "GLOBAL" }` → `200`, привязки очищены: вопрос ушёл со страницы услуги, появился на главной.
- `PATCH { scope: "TYPE" }` без вида → `400`, поле `equipmentTypeId`; `PATCH` несуществующего id → `404`.
- `POST` вопроса вида → `201`; `/api/landing?typeSlug=…` отдаёт его вместо общего списка.
- Преимущество: `POST` с `icon: "Fleet"` → `201` и `icon: "fleet"`; иконка «не иконка» → `400`, поле `icon`;
  `PATCH` текста → `200`, `/api/home` отдаёт новый текст.
- Шаг: `PATCH { isPublished: false }` → `200`, на главной пропал; возврат `true` — вернулся.
- Цифра: `POST` → `201`, `PATCH { unit: null }` → `200`; пустое значение → `400`, поле `value`.
- `DELETE` всех четырёх типов → `200`, публичный `/api/home` больше их не отдаёт; повторный `DELETE` → `404`.
- `/admin/content` с cookie → `200`; вкладки `?tab=stats|advantages|steps` рендерят свои секции,
  неизвестный `tab` — FAQ.

## Ограничения (осознанные)

- Порядок — числом `sortOrder`, без drag&drop: строк немного, число надёжнее при одновременной правке.
- Иконка преимущества — строковый ключ: предпросмотра нет, правильность проверяет фронтенд-дизайн-система.
- Ответ FAQ — обычный текст, markdown не поддерживается (в отличие от SEO-текстов услуг).
- FAQ не привязан к городу: списки общие для всех посадочных.
- Истории версий и отложенной публикации нет — только флаг `isPublished`.
- Удаление необратимо (подтверждение в браузере), корзины нет.
