## Зачем

Услуги — пять страниц `/uslugi/{код}`: земляные работы, вывоз грунта, демонтаж, планировка, перевозка
тралом. Публичные `/api/services`, `/api/services/{slug}` читают PostgreSQL на каждый запрос (кэша нет),
поэтому сохранение видно на сайте сразу. До слайса тексты и SEO-поля услуг менялись только сидом
или Prisma Studio.

## Контракт API

Все хэндлеры под `/api/admin/**`: middleware проверяет сессию и CSRF, в каждом хэндлере —
`requireAdmin(event)` (ADR-19, ADR-20). Ошибки — в общем формате
`{ message, data: { errors: [{ field, message }] } }`.

| Метод и путь | Назначение | Успех |
|---|---|---|
| `GET /api/admin/services` | все услуги, включая черновики; порядок как на сайте | `{ services }` |
| `POST /api/admin/services` | новая услуга | `201 { service }` |
| `PATCH /api/admin/services/:id` | правка только переданных полей | `{ service }` |
| `DELETE /api/admin/services/:id` | удаление и чистка редиректов на её адрес | `{ ok: true }` |

Коды ошибок: `400` — схема не прошла, `401` — нет сессии, `404` — услуги нет, `409` — занятый `slug`
(`P2002`) или у услуги есть вопросы FAQ.

Отдельной карточки `GET /:id` нет: услуг единицы, список отдаёт все поля (включая `seoText`), форма
открывается без дополнительного запроса. В списке также `faqCount` — таблица показывает число вопросов,
а `DELETE` по нему отказывает.

## Валидация (`shared/schemas/admin-services.ts`)

Схемы общие для формы и сервера; `slug`, `requiredText`, `optionalText`, `sortOrder` переиспользуются
из `shared/schemas/catalog.ts`.

| Поле | Правило |
|---|---|
| `slug` | правила каталога (2–80, латиница в нижнем регистре, цифры, дефис) |
| `title` | обязательный текст, 2–200 символов |
| `description` | необязательный, до 500 символов, пусто → `null` |
| `image` | необязательный адрес до 500 символов (значение `AdminImageField`) |
| `seoTitle` | необязательный, до 255 символов |
| `seoDescription` | необязательный, до 300 символов |
| `seoText` | markdown, до 20 000 символов |
| `sortOrder` | целое 0–100 000; при создании `10` |
| `isPublished` | boolean; при создании `true` |
| `PATCH` | `partial`-схема: отсутствующие поля не попадают в `data`, Prisma их не трогает |

## Адреса и редиректы (ADR-6)

- Услуга живёт по `/uslugi/{slug}` (`app/pages/uslugi/[slug].vue`).
- Смена кода: `serviceSlugRedirect` пишет `301` в `Redirect` (`upsert` по `from`) и сбрасывает кэш
  таблицы (`saveSlugRedirect`, `server/utils/catalog-slugs.ts`).
- Удаление услуги удаляет редиректы с `to = /uslugi/{slug}`: иначе старые ссылки уходили бы `301`
  в пустоту вместо `404`.

## Удаление и FAQ

`FaqItem.serviceId` объявлен с `onDelete: Cascade`, но удалять тексты вопросов «заодно» нельзя:
`DELETE` сначала считает `_count.faq` и при наличии вопросов отвечает `409`
(«К услуге привязано вопросов FAQ: N. Сначала удалите их»). После появления слайса `admin-content`
вопросы переносят или удаляют осознанно, а не каскадом.

## Экран

| Путь | Что |
|---|---|
| `/admin/services` | таблица: услуга и описание, `/код`, число вопросов, порядок, публикация, действия |

Форма создания и правки — одна, inline в `admin-subcard` (как разделы каталога): название, код, порядок,
краткое описание, изображение (`AdminImageField`), публикация и свёрнутый блок SEO-полей и markdown-текста.
«Открыть» ведёт на `/uslugi/{slug}` и показывается только у опубликованных. Ссылки добавлены
в навигацию админки и на дашборд; `/admin/services` открывается в широкой колонке.

## Проверено 16.11.2026 (dev на `:3999`)

- Без cookie `GET /api/admin/services` → `401`; `/admin/services` → `302` на вход с `next`.
- `POST` с пустым названием → `400`, ошибка по полю `title`; с кириллицей в коде → `400` по `slug`.
- `POST` тестовой услуги → `201`; публичный `/api/services` содержит её, `/api/services/{slug}` → `200`.
- `PATCH` со сменой кода → `200`; `/uslugi/{старый}` → `301` на новый адрес.
- Повторный `POST` с занятым кодом → `409` («Услуга с таким кодом уже есть»).
- `DELETE` услуги с привязанным вопросом FAQ → `409` («К услуге привязано вопросов FAQ: 1. Сначала удалите их»).
- `DELETE` услуги без FAQ → `200`; `/api/services/{slug}` → `404`, редирект на её адрес удалён.
- `/admin/services` с cookie → `200`, таблица и форма рендерятся; без cookie — `302`.

## Ограничения (осознанные)

- FAQ услуги редактируются в слайсе `admin-content`; здесь только счётчик и запрет удаления.
- Отдельного экрана-редактора нет: форма inline, длинный `seoText` — в свёрнутом блоке.
- Предпросмотра markdown нет: текст проверяется на сайте после сохранения.
- Истории версий и отложенной публикации нет — только флаг `isPublished`.
- Удаление необратимо (подтверждение в браузере), корзины нет.
