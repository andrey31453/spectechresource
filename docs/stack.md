Версии проверены через npm registry 15.11.2026 (не по памяти).

## 1. Базовое решение

| Слой | Выбор | Версия | Комментарий |

| Тесты | **Vitest** (unit) / Playwright (e2e) | 5.1.0 / 1.65.1 | unit подключён 15.11.2026; e2e — вместе с формами (ADR-16) |

## 2. Важные предупреждения по окружению (проверено на этой машине)

1. **Node по умолчанию в PATH — v20.11.1** (системная установка `/usr/local/bin/node`, 2024 г.), хотя `nvm` есть.
   Требования: `nuxt` — `^22.22.3 || ^24.15.0 || >=26.0.0`, `prisma` — `^22.18.0 || ^24.11.0 || >=26.0.0`.
   Доступно в registry: 22.23.5 и 24.22.3. **Выбрано: Node 24 LTS** (`.nvmrc` = `24`).
   **Установлено 15.11.2026:** `v24.22.3` (npm 11.19.1), `nvm use` по `.nvmrc` работает.
   Глобальный default nvm (20) не меняли; при работе в проекте — `nvm use`.
   Причина проблемы: `~/.nvm/alias/default` = `20`, а `/usr/local/bin` оказался раньше версии из nvm.
2. **`prisma` в npm помечен `latest` = `8.0.0-rc.33` — это pre-release.**
   Стабильная — `7.10.1` (dist-tag `prev`). Ставить явно: `prisma@7.10.1` и `@prisma/client@7.10.1`,
   иначе в проект прилетит RC.
3. **PostgreSQL локально не установлен** (`psql` отсутствует), но есть **Docker 24.0.7** →
   база поднимается контейнером (`docker compose`), на прод — managed PostgreSQL в РФ.
4. npm: 11.19.1 вместе с Node 24.22.3; системный npm 10.2.4 (Node 20.11.1) остаётся, но не используется в проекте.
5. **Порт 5432 на машине занят** (контейнер `backend-nest-postgres-1` из другого проекта) →
   PostgreSQL проекта `spectech` опубликован на хосте **5433** (`docker-compose.yml`, `.env`: `localhost:5433`).
   Внутри контейнера порт по-прежнему 5432.
6. **Prisma 7 работает только через driver adapter** (ADR-11): `new PrismaClient()` без аргументов падает
   с `PrismaClientInitializationError: PrismaClient was instantiated without any options`. Правильно:
   `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`.
7. **`npx prisma` не читает `.env` сам** — конфиг `prisma7.config.ts` подключает `dotenv`; в скриптах,
   запускаемых через `tsx` (сид), нужен свой `import "dotenv/config"`.

## 3. Как стек закрывает требования ТЗ

| Требование ТЗ | Решение в стеке |
|---|---|
| SEO-мета на каждой странице | `useSeoMeta`/`useHead` + шаблоны из БД, SSR-рендеринг |
| `sitemap.xml`, `robots.txt` | модули `@nuxtjs/sitemap` и `@nuxtjs/robots` (генерация из данных каталога) |
| Микроразметка Organization / Product-Offer / FAQ / Breadcrumb | `nuxt-schema-org` + `defineBreadcrumb`, `defineProduct`, FAQPage вручную/хелпером |
| ЧПУ `/arenda-{vid}-v-{gorod}/` | роут + поиск по `slug` в БД, 404 при отсутствии (шаблон зависит от Q-01) |
| Формы → Битрикс24 | Nitro server route `/api/leads`: valibot-валидация → запись в `Lead` → REST вебхук Битрикс24 |
| Страница-источник и UTM в лиде | сервер получает `pageUrl`/`utm_*` из запроса и заголовков, подставляет в поля лида |
| Яндекс.Метрика + цели | плагин + `reachGoal` по событиям, ID счётчика из `SiteSettings` |
| Редактирование каталога заказчиком | `/admin` на Nuxt + серверные API + сессия в httpOnly-cookie (`nuxt-auth-utils`) |
| WebP, PageSpeed ≥ 70 | `@nuxt/image` + конвертация при загрузке, отложенная загрузка счётчика и карты |
| Согласие ПДн | обязательный чекбокс + сохранение `consentAt`/`consentVersion` в `Lead` |

## 6. Правила по версиям

- `prisma` и `@prisma/client` — **точные версии** (без `^`), обе одинаковые.
- Остальные зависимости — `^`, lock-файл коммитится.
- Новые зависимости — только с согласия (см. `AGENTS.md`).

## 8. Журнал решений (ADR)

| ID | Дата | Решение | Почему | Последствия |
|---|---|---|---|---|
| ADR-1 | 15.11.2026 | Админка — **своя, на Nuxt + Prisma** (вместо headless CMS) | Одна кодовая база и один деплой, прямой доступ к Prisma-схеме; заказчику нужны CRUD по каталогу и журнал заявок, а не полноценная CMS | Пишем UI и авторизацию сами; headless CMS можно добавить позже поверх той же БД |
| ADR-2 | 15.11.2026 | PostgreSQL локально в **Docker Compose**; на прод — контейнер на VPS в РФ или managed PG | Одинаковое окружение у разработчика и на проде; 152-ФЗ требует хранения ПДн в РФ | Нужен работающий Docker; бэкапы настраиваются отдельно |
| ADR-3 | 15.11.2026 | **Node 24 LTS** (`.nvmrc` = `24`) | Удовлетворяет `engines` Nuxt 4.6 и Prisma 7, дольше поддерживается, чем 22 | Прод-образ тоже `node:24` |
| ADR-4 | 15.11.2026 | Prisma ставится **точной версией 7.10.1** | npm dist-tag `latest` = `8.0.0-rc.33` (pre-release) | Версии `prisma` и `@prisma/client` синхронизируются вручную |
| ADR-5 | 15.11.2026 | Заявка сначала в **БД** (`Lead`), затем в Битрикс24 | Лид не теряется при недоступности CRM | Очередь, ретраи, статусы и ручная переотправка в админке |
| ADR-6 | 15.11.2026 | URL **без завершающего слеша**; вариант со слешем → 301 | Единая политика canonical, меньше дублей | Правило закрепляется в роутинге и sitemap |
| ADR-7 | 15.11.2026 | Стили — **Tailwind CSS 4** (без отдельного UI-кита на старте) | Быстрая консистентная вёрстка, дизайн-токены в конфиге, нет лишних зависимостей | Компоненты пишем свои поверх утилит; при необходимости позже добавляем headless-компоненты |
| ADR-8 | 15.11.2026 | Разработка — **только локально**; деплой и хостинг определяем позже | Заказчик ещё не решил, где будет прод | Код и конфиги держим переносимыми (Docker), никаких привязок к конкретному хостингу |
| ADR-9 | 15.11.2026 | Деньги — **`Decimal @db.Decimal(12,2)`**, а не `Int` рублей | Подтверждено заказчиком: точность до копейки без ручных пересчётов; `Int` потребовал бы миграции при первом же дробном тарифе | Prisma отдаёт `Decimal`, на API сериализуем строкой, форматирование — в UI-хелпере |
| ADR-10 | 15.11.2026 | Город — **отдельная таблица `City`** + `SiteSettings.cityId`, вместо полей `city`/`cityIn` | Городов может стать больше одного (Q-01), добавление не требует миграции схемы | Город подтягивается через `include`; `City.nameIn` («Москве») — для H1 и ЧПУ |
| ADR-11 | 15.11.2026 | Prisma Client создаётся **только с driver adapter** `@prisma/adapter-pg` | В Prisma 7 удалён Rust-движок: `new PrismaClient()` без адаптера падает при инициализации | Один экземпляр клиента на процесс; `datasource db` без `url`, строка — в `prisma7.config.ts` |
| ADR-12 | 15.11.2026 | Слаги видов техники — **по ТЗ, в родительном падеже** (`/arenda-gusenichnogo-ekskavatora`) | URL уже заданы в ТЗ и согласованы с SEO-структурой; менять их позже — терять индексацию | `EquipmentType.slug` = слаги из ТЗ, `name` (именительный) — для меню и хлебных крошек |
| ADR-13 | 15.11.2026 | SEO-обвязку делаем **без `@nuxtjs/seo`**: `sitemap.xml` и `robots.txt` — Nitro-роуты (`server/routes/`), мета и JSON-LD — `useSeoMeta` + свои композаблы | Нужен точный контроль: 39 ЧПУ из БД, таблица `Redirect`, один H1, предсказуемый JSON-LD. Пакет `@nuxtjs/seo` тянет og-image и link-checker, которые на этом этапе не нужны | Меньше зависимостей и вес сборки; проверяется `curl`. `og-image`/валидатор ссылок при необходимости ставим точечно, `@nuxt/image` — в слайсе фронтенда, `valibot` — в `leads` (ADR-17) |
| ADR-14 | 15.11.2026 | Markdown статических страниц и SEO-текстов рендерим **на сервере мини-рендерером** (`server/utils/markdown.ts`) с экранированием HTML | Сейчас нужны только заголовки, абзацы, списки, цитаты и ссылки; полноценный редактор появится вместе с админкой | Свойства безопасны (HTML экранируется), нет лишней зависимости; при появлении сложной разметки заменяем на `marked` в слайсе админки |
| ADR-15 | 15.11.2026 | **TypeScript 5.9.3**, а не 7.0.2 | `typescript-eslint@8.72` и `ts-api-utils@2.5` обращаются к `ts.TypeFlags.Intrinsic`, которого в TS 7 нет: линтер падал с `TypeError: Cannot read properties of undefined (reading 'Intrinsic')` | Пока линтер — часть DoD, держим TS 5.9.3; на TS 7 переходим, когда `typescript-eslint` объявит поддержку |
| ADR-16 | 15.11.2026 | Тестовый контур: **Vitest 5** (unit) + **`@nuxt/eslint` 1.17** (flat config); тесты — на чистых функциях; API-интеграция — через сервисный слой слайса `leads` | Нужны быстрые тесты без поднятия Nuxt/Nitro и БД; `@nuxt/test-utils` тянет полную сборку и пока не оправдан | `npm test` — 36 unit-тестов, `npm run typecheck` — только `.ts`; `.vue`, Playwright и тесты API с БД — в следующих слайсах (`vue-tsc`/`@nuxt/test-utils`) |
| ADR-17 | 15.11.2026 | Валидация — **valibot 1.5.0** вместо zod 4.6.7 | Решение заказчика. Модульные схемы-функции (`v.pipe`, `v.transform`) позволяют нормализовать телефон прямо в схеме, в клиентском бандле valibot ≈1,5 КБ против ≈14 КБ у zod | Схемы — `shared/schemas/leads.ts` (Nuxt 4 `sharedDir`), одна схема для формы и для `POST /api/leads`; сообщения об ошибках пишем в правилах по-русски, `@valibot/i18n` не нужен. Проверено 15.11.2026 на Node 24: `v.pipe`/`v.transform`/`v.safeParse` работают, `h3@1.15.11` валидирует через `validateData(data, fn)` — привязки к конкретной библиотеке нет. zod остаётся в lock-файле только транзитивно (dev, `@modelcontextprotocol/*` из Nuxt-тулинга) |

> ADR-6 предварительный: применяем, если нет возражений заказчика/SEO-специалиста.
