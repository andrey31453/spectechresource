## 2. Важные предупреждения по окружению (проверено на этой машине)

1. **Node по умолчанию в PATH — v20.11.1** (системная установка `/usr/local/bin/node`, 2024 г.), хотя `nvm` есть.
   Требования: `nuxt` — `^22.22.3 || ^24.15.0 || >=26.0.0`, `prisma` — `^22.18.0 || ^24.11.0 || >=26.0.0`.
   Доступно в registry: 22.23.5 и 24.22.3. **Выбрано: Node 24 LTS** (`.nvmrc` = `24`).
   **Установлено 15.11.2026:** `v24.22.3` (npm 11.19.1), `nvm use` по `.nvmrc` работает.
   Глобальный default nvm (20) не меняли; при работе в проекте — `nvm use`.
   Причина проблемы: `~/.nvm/alias/default` = `20`, а `/usr/local/bin` оказался раньше версии из nvm.
2. **`prisma` в npm помечен `latest` = `8.0.0-rc.33` — это pre-release.**
   Стабильная — `7.10.1` (dist-tag `prev`). Ставить явно: `prisma@7.10.1` и `@prisma/client@7.10.1`,
   иначе в проект прилетит RC.
3. **PostgreSQL локально не установлен** (`psql` отсутствует), но есть **Docker 24.0.7** →
   база поднимается контейнером (`docker compose`), на прод — managed PostgreSQL в РФ.
4. npm: 11.19.1 вместе с Node 24.22.3; системный npm 10.2.4 (Node 20.11.1) остаётся, но не используется в проекте.

## 3. Как стек закрывает требования ТЗ

| Требование ТЗ | Решение в стеке |
|---|---|
| SEO-мета на каждой странице | `useSeoMeta`/`useHead` + шаблоны из БД, SSR-рендеринг |
| `sitemap.xml`, `robots.txt` | модули `@nuxtjs/sitemap` и `@nuxtjs/robots` (генерация из данных каталога) |
| Микроразметка Organization / Product-Offer / FAQ / Breadcrumb | `nuxt-schema-org` + `defineBreadcrumb`, `defineProduct`, FAQPage вручную/хелпером |
| ЧПУ `/arenda-{vid}-v-{gorod}/` | роут + поиск по `slug` в БД, 404 при отсутствии (шаблон зависит от Q-01) |
| Формы → Битрикс24 | Nitro server route `/api/leads`: zod-валидация → запись в `Lead` → REST вебхук Битрикс24 |
| Страница-источник и UTM в лиде | сервер получает `pageUrl`/`utm_*` из запроса и заголовков, подставляет в поля лида |
| Яндекс.Метрика + цели | плагин + `reachGoal` по событиям, ID счётчика из `SiteSettings` |
| Редактирование каталога заказчиком | `/admin` на Nuxt + серверные API + сессия в httpOnly-cookie (`nuxt-auth-utils`) |
| WebP, PageSpeed ≥ 70 | `@nuxt/image` + конвертация при загрузке, отложенная загрузка счётчика и карты |
| Согласие ПДн | обязательный чекбокс + сохранение `consentAt`/`consentVersion` в `Lead` |

## 6. Правила по версиям

- `prisma` и `@prisma/client` — **точные версии** (без `^`), обе одинаковые.
- Остальные зависимости — `^`, lock-файл коммитится.
- Новые зависимости — только с согласия (см. `AGENTS.md`).

## 7. Порядок инициализации (когда будет команда «старт»; сейчас НЕ выполнялось)

1. `nvm install 24.22.3 && nvm alias default 24.22.3 && nvm use 24.22.3` — проверить `node -v` и `which node`.
2. Запустить Docker Desktop, затем `docker compose up -d postgres` — локальная БД.
3. Инициализация Nuxt 4 в корне проекта.
4. Установка: `prisma@7.10.1`, `@prisma/client@7.10.1`, `@nuxtjs/seo`, `@nuxt/image`, `zod`.
5. `.env`: `DATABASE_URL`, `BITRIX24_WEBHOOK_URL`, `NUXT_PUBLIC_METRIKA_ID`, `SESSION_SECRET` (секреты только в `.env`, не в репозитории).
6. `prisma migrate dev` + сид: 6 разделов, 39 видов техники, демо-модели и цены.

## 8. Журнал решений (ADR)

| ID | Дата | Решение | Почему | Последствия |
|---|---|---|---|---|
| ADR-1 | 15.11.2026 | Админка — **своя, на Nuxt + Prisma** (вместо headless CMS) | Одна кодовая база и один деплой, прямой доступ к Prisma-схеме; заказчику нужны CRUD по каталогу и журнал заявок, а не полноценная CMS | Пишем UI и авторизацию сами; headless CMS можно добавить позже поверх той же БД |
| ADR-2 | 15.11.2026 | PostgreSQL локально в **Docker Compose**; на прод — контейнер на VPS в РФ или managed PG | Одинаковое окружение у разработчика и на проде; 152-ФЗ требует хранения ПДн в РФ | Нужен работающий Docker; бэкапы настраиваются отдельно |
| ADR-3 | 15.11.2026 | **Node 24 LTS** (`.nvmrc` = `24`) | Удовлетворяет `engines` Nuxt 4.6 и Prisma 7, дольше поддерживается, чем 22 | Прод-образ тоже `node:24` |
| ADR-4 | 15.11.2026 | Prisma ставится **точной версией 7.10.1** | npm dist-tag `latest` = `8.0.0-rc.33` (pre-release) | Версии `prisma` и `@prisma/client` синхронизируются вручную |
| ADR-5 | 15.11.2026 | Заявка сначала в **БД** (`Lead`), затем в Битрикс24 | Лид не теряется при недоступности CRM | Очередь, ретраи, статусы и ручная переотправка в админке |
| ADR-6 | 15.11.2026 | URL **без завершающего слеша**; вариант со слешем → 301 | Единая политика canonical, меньше дублей | Правило закрепляется в роутинге и sitemap |
| ADR-7 | 15.11.2026 | Стили — **Tailwind CSS 4** (без отдельного UI-кита на старте) | Быстрая консистентная вёрстка, дизайн-токены в конфиге, нет лишних зависимостей | Компоненты пишем свои поверх утилит; при необходимости позже добавляем headless-компоненты |
| ADR-8 | 15.11.2026 | Разработка — **только локально**; деплой и хостинг определяем позже | Заказчик ещё не решил, где будет прод | Код и конфиги держим переносимыми (Docker), никаких привязок к конкретному хостингу |

> ADR-6 предварительный: применяем, если нет возражений заказчика/SEO-специалиста.
